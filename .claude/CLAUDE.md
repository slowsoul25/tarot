# 慢靈魂 tarot 網站

使用者目前的名稱（品牌全名）：**🌿慢靈魂｜🔮塔羅占卜・靈擺問事・能量調頻**。IG 帳號 @slowsoul_tarot。需要寫到名稱的地方都用這個。

這個 repo 是慢靈魂的大眾占卜解答網站，根目錄的 `慢靈魂解答_<題目>.html` 都是解答頁，直接放在 `main`（使用者同意解答頁直接上傳到 `main`）。

## 使用者說「上傳」時的流程

解答頁是用 claude.ai 上的製作器「慢靈魂｜塔羅測驗產生器」做的：
https://claude.ai/artifact/XTM5brJrKxe2McUn4BmqKg
製作器不要搬到別處（它的 AI 出題／解答／調頻和雲端存檔只在 claude.ai 上能用）；要改功能時，改完用 Artifact publish 帶 `url` 發佈回同一個網址。

1. 用 Artifact 工具 `action: "read"` 讀製作器，得到存好的完整 HTML 路徑（tool-results 裡的 artifact-*.html）。
2. 用 ArtifactData `get` 抓雲端這一期：`url` 同上、`collection: "data/users/me"`、`doc_id: "generator"`，加 `out_dir` 存成 JSON。
3. 執行：
   `NODE_PATH=$(npm root -g) node .tools/build-answer.js <製作器.html> <generator.json> <輸出資料夾>`
   會用製作器自己的 `buildWebA` 產生跟「⬇️ 下載解答網頁 HTML」一樣的檔案，檔名也一樣。
   - `NO_ANSWERS`：三個解答還沒寫好。
   - `NO_IMAGES`：牌面用的是使用者自己上傳的照片（只存在他的瀏覽器，雲端沒有），做出來的圖會不一樣。請使用者在製作器按「⬇️ 下載解答網頁 HTML」，把下載的檔案傳給你，直接上傳那個檔案。
   - `NO_BG`：背景是使用者自己上傳的照片，雲端沒有。請使用者把背景圖傳給你，或在製作器下載解答網頁 HTML 傳給你。
   - `NO_TUNE` / `NO_THEME`：請使用者在製作器按一次「👀 預覽解答網頁」（會配調頻、決定色調並存雲端），再重跑。
4. 跟使用者確認題目對（雲端存的是製作器「目前打開的那一期」）。同名檔案已存在時先問要不要覆蓋。
5. 把檔案放到 repo 根目錄，commit 訊息用 `新增解答：<題目>`，推到 `main`。
6. 給使用者網址：`https://slowsoul25.github.io/tarot/<檔名 URL 編碼>`（若網站網址不同以使用者為準）。

## 製作器的圖庫

使用者要把圖片「加進製作器圖庫」時：讀製作器 HTML，把圖片加到 `BGLIB` 陣列最後（`{"c":分類,"n":名稱,"d":dataURL}`，id 依順序自動是 `b<index>`），再在 `OBJLIB` 最後加 `{"id":"o<新號碼>","n":名稱,"f":色系,"fs":[色系...],"ref":"b<對應背景 id>","k":分類}`，這樣同一張圖可以當背景也可以當選項圖。用 bytes 操作插入（檔案裡有控制字元），用 `.tools` 外的暫存腳本測試渲染後，再用 Artifact publish 帶 `url` 發佈。

## 背景規則（使用者設定）

- 解答網頁會帶上出題篇第一頁的背景，上面蓋一層跟色調一樣的淡霧（製作器 `buildWeb` 已內建，`.tools/build-answer.js` 走同一套）。
- 用過的背景不再出現在圖庫：製作器在「預覽／下載解答網頁」時把這期的背景記進 `S.usedBg`（會同步到雲端），圖庫和隨機挑背景都會跳過它。不要真的從 BGLIB 刪資料，舊的期數還會用到。

## 使用者說「下一篇」時的流程

使用者選擇：題目由 Claude 出、使用者選；抽牌和寫解答照常在製作器裡按。

1. 先看出過的題目：repo 根目錄所有 `慢靈魂解答_*.html` 的題目，加上雲端 `generator` 的 `past`，都不能重複或太像。
2. 照製作器 `hookPrompt()` 的規則想題目（熱門大眾題型平均分散：分數／程度、時間／月份運勢、認識自己、課題／卡點、對方心意、輕鬆好玩；感情題約一半）：
   - 題目最多 2 行、每行最多 11 字、整句 20 字內，兩行長度平均，用 `\n` 斷行
   - 引言 1 行、最多 18 字，說出讀者看到題目時心裡卡的感受；不能用問號、不能反問、不重複題目的字、不要編無關場景、不用引號
   - 繁體中文台灣口語
3. 用 AskUserQuestion 跳 4 個題目讓使用者選（label 放題目，description 放引言和題型），使用者也可以自己打。
4. 用 ArtifactData `set` 寫進**另一份文件** `collection: "data/users/me"`、`doc_id: "claudeNext"`（不要寫進 generator，製作器同步時會把 generator 整份蓋掉）：
   `{"id":"q<現在的毫秒時間>","title":"第一行\n第二行","intro":"引言"}`（文件已存在時先 get 拿 version 再帶 `if_version`）。
   製作器打開時、之後每 8 秒、切回分頁時會檢查這份文件，套用後就刪掉它，並把 id 記在 `S.nextDone`；套用時會存好上一期、換上題目和引言、清空抽牌和解答、隨機換沒用過的背景和牌面圖。
5. 告訴使用者打開或重新整理製作器，接著按「抽牌並寫解答」。

## 題目排隊（`.tools/queue.json`）

使用者選擇把投稿題目排隊、一篇接一篇做。`.tools/queue.json` 是還沒換上的題目（第一個是下一篇）。
- 使用者說「上傳」：照上傳流程傳完後，如果 queue 還有題目，就取出第一個，用「下一篇」流程第 4 步寫成 `nextTopic`，從 queue 刪掉並 commit。回覆時告訴使用者已換上哪個題目、還剩幾篇。
- 使用者丟來新的投稿：整理成題目（規則同「下一篇」第 2 步，太籠統的跳過，跟網站已有的太像就換角度），加到 queue 最後。

## 解讀規則（使用者設定）

- 預設每個選項抽 3 張，無牌陣：不分位置、不分順序，三張合在一起讀成一個完整狀況（製作器 `runAnswers` 已改：`LN=null`、`BASE=OV||3`）。解讀方向寫了「每個選項抽 N 張」才改張數；題目問時間仍會多一張時間牌。
- 口吻要很口語、像她本人講話的台灣口語，不要文章感、不要 AI 感；製作器 `VOICEf()` 會附上她本人的口吻範例（`S.voiceS`，預設是 `VOICE_DEFAULT`）。
- emoji：每個選項 3～4 個（不好的結果約 2 個溫和的 🥺🌙🤍），直接接在句尾取代逗號／句號、後面空一格，跟著那句的情緒放。
- 感情題的曖昧／交往／分手：照題目最可能的狀況寫主線，答案會差很多的題目（顧慮、未來、會不會回頭）在第二段用一兩句帶到其他狀況（如果你們還在曖昧…已經在一起的話…分手後的話…），不分開寫成大段。
- 顧慮／原因／卡點題：第一段具體講出是什麼（head 也寫出來），第三段講讀者做得到、對準那個顧慮的緩解做法，不能只叫讀者等、問他、想清楚自己。
- 講解要適當多補充：講到 不滿意／擔心／失望／不安／壓力／卡住 這類籠統的詞，要用「可能是…或是…」補一句是在什麼上面，方向要從牌（花色、牌義）推得出來（VOICE0【補充說明】）。
- 段落：固定三段（第一段只放答案、第二段原因和狀態、第三段怎麼做和收尾），段落之間只換一行不空行（單一 `\n`）。解答網頁模板 `.answer .body p`：段落間 12px 小空隙、16px 字、字距 .4px、左右對齊，第一段字加深。「從牌面上看起來」可以視情況用，一個選項最多一次、三個不要都用。
- 標點：標點像使用者傳訊息那樣多用逗號接下去，整段大概兩三個句號，不要驚嘆號、刪節號；語氣溫暖、有溫度（VOICE0【標點和溫度】）。
- 每個選項寫成一個串在一起的故事：段落之間有因果和接續，不要一張牌一段、一個重點一段，讀不出哪句來自哪張牌（VOICE0【串在一起】）。
- 用詞要現代、像一般台灣人聊天會講的詞；製作器 VOICE0 的【用詞】有一份 AI／心靈雞湯詞的禁用清單（含使用者以前存的 banW），書面詞要換口語（給予→給、尚未→還沒、是否→是不是…）。
- 「感覺」整篇最多一次，不要 有沒有感覺／有感覺／沒感覺／這種感覺／給我的感覺，改用 心動、在意、喜歡、想靠近、放在心上 這類具體說法（使用者自己的占卜也常出現，覺得很制式）。
- 不要套路化的日常情境（回訊息、已讀不回、看限動、主動約、吵架誰先開口），重點放在心裡的感受、想法和狀態；只有牌非常明確指向時才寫，整篇最多一句。
- 每個選項都用「選到A的小靈魂，」開頭（使用者要保留這個語氣），後面接的講法三個不同。
- 語氣照 SOP（https://claude.ai/artifact/FXiKGgaG57GeSX8jLEha5K 的「解讀風格」）：語音轉文字感、句子可以長、用然後／就是／那／所以／只是一路接下去，不要斷太快；也參考使用者在對話裡講話的樣子。製作器 VOICEf() 已附 SOP 語氣、SOP 範例和使用者的訊息範例。
- 結尾照 SOP（11/23）：最後一段用「所以、那」順順接下去，給一個做得到的下一步（時機、先處理的卡點、先不要做的事、可以怎麼開口），不要收在「回到自己身上／把力氣放回自己／先把自己顧好／把期待收回來」這類講法，安慰句不要放最後。
- 不要制式：結尾不固定收在「會更清楚、更知道自己要什麼…喔」、三個選項的段落順序和開頭結尾都要不同。
